# THREADLINE V1.6 — Camera Scanner & Outfit Integrity (test lab)

## Why this update

Older LAB photos were uploaded with random filenames (such as IMG_...) and categorized as **Tops**, regardless of what the photograph showed. A photo of boots or trousers could therefore enter the Top slot while the Stylist also inserted a separate bottom and shoe. Those are **not alternatives**. Each recommended outfit must have exactly one top, one bottom and one pair of shoes, with an optional layer and accessory.

## Shipped in the V1.6 testing lab

- A single-slot validator `lab/v16/assets/outfit-rules.js` checks counts and requires manual category confirmation.
- **Unverified legacy imports are excluded from generation** until re-reviewed. Previously saved photos are kept intact. Open **Wardrobe Scanner → Review all saved items**, correct the category, garment type and name, then Save all.
- The Stylist labels TOP, BOTTOM, SHOES, OPTIONAL LAYER and OPTIONAL ACCESSORY, explains which items are part of the outfit, and separates shopping alternatives from outfit pieces.
- The three looks prefer different footwear/bottoms when the confirmed wardrobe contains enough options. If only one suitable bottom exists, repeats may be unavoidable and should be described rather than disguised.
- Mobile **Take photo** uses the browser camera/file picker (where supported).
- **Open live camera** uses permissioned `getUserMedia` on HTTPS and captures individual JPEG stills using a canvas; stop closes all tracks. Works with a desktop webcam too. Bulk upload remains available.
- Both camera paths feed the existing editable, local-only draft review; a captured image does **not** imply AI classification.

## Actual AI image recognition — code prepared, not yet activated

`supabase/functions/threadline-vision/index.ts` is a Supabase Edge Function for a **pretrained vision-capable model**. You do **not** need to train a new model from scratch. The model will infer category, garment type, approximate color, possible fit and optional style terms from the photo. It returns a structured prediction with a confidence label and note; no result is ever auto-saved.

The browser uses `lab/v16/assets/vision-client.js` to call the function after the user explicitly clicks **Analyze with AI**, sees consent messaging, and is signed in to THREADLINE. No AI credentials are in the browser or GitHub.

### One-time activation (not necessary to test camera or outfit fixes)

1. Set up a separate provider API account/usage budget. The existing ChatGPT subscription does not automatically include API credits. Avoid submitting private photos without consent.
2. In Supabase **Edge Functions**, deploy a new function named `threadline-vision` using the code in `supabase/functions/threadline-vision/index.ts`. You may use the Supabase CLI or Dashboard function editor.
3. Leave the default JWT verification **enabled**. The function rechecks the signed-in user, restricts CORS to the THREADLINE GitHub Pages origin, limits image payload size, and uses an allowlist.
4. In Supabase **Edge Function Secrets**, set these **server-side only** (never send secrets through chat or commit them):
   - `OPENAI_API_KEY`: your private vision provider API key
   - `VISION_ALLOWED_EMAILS`: comma-separated verified sign-in emails allowed to test
   - `VISION_ENABLED`: `true`
   - Optional `VISION_MODEL`: `gpt-4o-mini` (default; supported vision/structured outputs)
5. Open the V1.6 Wardrobe Scanner from **the same browser where you are signed into THREADLINE**. No new Supabase redirect URL, database table, or storage bucket is needed.
6. In a draft, click **Analyze with AI** to send **that one compressed clothing photo**. The prediction is editable. Confirm before saving.
7. Monitor the provider usage dashboard. The allowlist and payload limit reduce abuse but are **not billing quotas**. Set provider project spending controls, and add server-backed rate limits before exposing public AI access.

The original GitHub code update did not deploy or call the function; it was subsequently deployed on November 7, 2026 with JWT verification enabled, but model calls have not been verified; the button will display a configuration/unavailable message until the above setup is complete. Keep using manual classification in the meantime. API inference may be wrong, especially with overlapping garments, poor lighting or ambiguous fit.

## Second lab iteration — easier review, inspiration AI and missing image recovery

The wardrobe scanner originally guessed labels from camera filenames and center-pixel averages. It is **not** a visual classifier. It now provides:
- Per-photo **quick category chips** (Tops, Bottoms, Shoes, Outerwear, Accessories) that assign an appropriate generic garment type instead of assuming every unknown item is a shirt.
- A **Suggest name from selected type** control to replace unhelpful old auto-generated names.
- A **fast batch review**: select multiple drafts, apply a shared category, then explicitly confirm only photos you have verified. Batch operations never silently approve the image classification.
- Optional **Analyze selected with AI**, restricted to 5 photos per batch, with a confirmation that each photo is sent to a paid third-party model. AI suggestions stay as editable drafts and never auto-save.
- Larger 1100-pixel compressed photos for potential AI interpretation, with manual color kept separate from the approximate background-affected pixel sample.
- Broader garment vocabulary, including jerseys, polo shirts, joggers, track pants, more shoe varieties, and multicolor garments.

The Inspiration Board now includes an optional **Interpret the photo with AI** button, next to the existing text-to-fashion-language helper. The shared `threadline-vision` Edge Function supports `task: "garment"` or `task: "inspiration"` and uses high-detail image input to return structured suggestions. Once the user consents and visual analysis is available, inspiration results include garment descriptions, a style explanation, editable theme tags, and possible directions. Saved theme tags flow into the Stylist and saved visual insights appear alongside the reference photos.

**UPDATE (November 7): The function is deployed with JWT verification enabled, but the AI service is not yet enabled or verified.** Until you connect Supabase and enable it, the app reports that visual AI is unavailable and continues to support manual categorization/text interpretation. No API key is exposed in the public site. Visual-model suggestions may still be incorrect; always review them.

Third-party reference imagery sometimes fails to load because retailer image URLs can change or block embedding. The Stylist now handles image failures gracefully, replacing the broken tile with a garment-category graphic and retaining its shopping/search link. This avoids empty cards but is not a guarantee of full outfit photography. Full composite outfit images require a separate visualization feature.
