# THREADLINE V1.6 — Personal Style Intelligence (non-AI release candidate)

## Release status

**Production V1.5 remains unchanged.** The V1.6 app changes are on `feature/v16-non-ai-personal-stylist`, while a separately isolated **full-app guest preview** runs at:

https://axelsalassanchez07-spec.github.io/Threadline/v16-preview/

The permanent V1.6 lab still exists at `/lab/v16/` but is now used for *future* experiments, not as the intended production app.

## What V1.6 adds directly to the real app

### Wardrobe onboarding
- **Bulk upload / scan** appears in My Wardrobe. Select up to 20 existing clothing photos or capture one with the phone camera picker.
- Photos are compressed and held in editable drafts. There is **no automatic image recognition** or filename-based claim of detection.
- Select multiple photos, assign one category (Tops / Bottoms / Shoes / Outerwear / Accessories), adjust garment type/name/color/fit/tags, then explicitly confirm the type matches each picture.
- Only confirmed batches are written into the real `items` store; the existing Supabase cloud sync hooks handle logged-in production saves after release.
- No migration or new Supabase SQL table.

### Inspiration Board
- A **Style Intelligence** panel identifies recurring *user-written* style cues and recent patterns across the existing `inspos` store.
- In the Add Inspiration form, the note you type is translated into suggested fashion vocabulary (e.g. baggy trousers → relaxed / wide-leg, cropped jacket → cropped). Suggestions can be added back to the note and edited before saving.
- The existing inspiration image, title, color and garment fields are still stored normally. Image pixels are not analyzed.

### Personal Stylist
- The existing Shop Real Looks / Discover generator now has a **plain-language outfit direction**, a Familiar/Balanced/Experimental creativity setting and **Explore three directions**.
- Recreate / Reinterpret / Explore show actual owned clothing or catalog references with their original product photos, cost-to-buy estimate, clear garment roles and optional shopping-search links.
- The V1.5 generated-look archive, ratings and saved shopping looks are preserved. Scoring now discourages recently repeated outfit silhouettes, especially in Experimental mode.
- The underlying catalog is still 13 static retailer products, with static reference prices and links. Shopping searches are not live integrated inventory; no invented prices or availability.
- Preferences are stored under the existing `prefs` row (`v16Prompt` and `v16Creativity`) and are included automatically in the existing Supabase cloud snapshot.

### What we intentionally postponed to V1.7
- Paid visual garment classification and image-based inspiration analysis; existing Edge Function remains separate and is not called by these production V1.6 features.
- Optional free/offline models such as browser CLIP or MediaPipe require model downloads and accuracy/device testing before acceptance.
- Ingesting live retailer catalogs, prices, and fashion trends. The current release offers manually grounded catalog references and external discovery searches, not live feeds.

## Safe functional tests before production merge

1. Open the **V1.6 preview** URL. Confirm the green banner says **SAFE LOCAL PREVIEW — No Supabase connection**.
2. Open My Wardrobe → **Bulk upload / scan**. Choose 4–8 photos. Each must appear in the queue with an editable name/category/type/fit/color/tags field.
3. Apply a category to selected items. Confirm **unverified photos cannot be saved**. Individually inspect each selected photo, confirm valid types, save and refresh.
4. Check that all approved pieces appear in the wardrobe with their original photos and correct categories. Test capturing one item on a phone if available.
5. Open Inspiration Board, save one or more references with plain-English notes such as 'I like wide trousers and a cropped jacket'. Check the style summary reports relevant patterns, and that the note-to-fashion translator offers editable suggestions.
6. Open Outfit Studio → Discover or Shop Real Looks. Enter a desired look, save preferences, and try Familiar / Balanced / Experimental.
7. Click **Explore three directions**. The cards should show different ideas where available, and clearly label **one top + one bottom + one pair of shoes**, with optional layer.
8. Click **Use this combination**. Confirm the specific outfit is selected in the normal Shop/Studio interface and any retail images and links remain accurate.
9. Rate a generated outfit, then check the original **Outfit archive** and Saved Outfits views. Refresh and confirm preferences, wardrobe and archive persist in preview.
10. Open your **production V1.5** home page in another tab and confirm the real wardrobe is unchanged.

### Before eventual merge
- Export a production backup from Style Profile.
- Cross-check preview fixes on mobile and desktop.
- Merge the V1.6 PR only after the user's acceptance testing.
- Verify main deployment, Google/GitHub login, cloud data restore, and a one-item sync PC → phone.
- If anything fails, revert via the existing release backup branch or a new release-specific rollback ref.

## Technical details
- Main app integration consists of `style-language.js`, `wardrobe-bulk-v16.js`, `style-v16.js`, `style-v16.css` and a scoring update in `outfit-discovery.js`.
- Preview files are copied under `v16-preview/` on `main` for GitHub Pages without merging the new production homepage.
- Preview's IndexedDB and shopping localStorage keys are separately namespaced; account/cloud JS is **omitted**.
- The preview has no realtime sync. Production after merge retains existing Supabase hooks, which include `items`, `inspos`, `prefs`, `shoppingV11` and feedback.
