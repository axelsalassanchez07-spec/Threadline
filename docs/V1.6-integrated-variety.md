# V1.6 integrated wardrobe and variety

Production entry point now loads the previously separate wardrobe review and stylist controls, using the existing IndexedDB stores and cloud write hooks. No database migration or auth change.

## Diagnosis
The starter retailer catalog has 13 products and only three tops. V1.5 excludes exact combinations but permits near repeats, rewards unrelated style tags, and only considers the first ten owned pieces per category. Preview explanations list Unknown as a color. Category edits can leave stale generic item names.

## Changes
- Discovery uses all valid wardrobe entries. Mixed category/type records and explicitly unconfirmed items are excluded; legacy manually added entries with consistent labels remain eligible.
- Three-direction batches require different top families, different bottom/shoe combinations, at least two changed garment families and at most one shared product. Fewer results are shown when insufficient variety exists.
- Recent-item reuse is penalized across generations. Known shared styling details, written preferences and ratings guide ranking. Budget-matching options take precedence; unavoidable over-budget results are labeled.
- Concrete styling explanations and wear tips replace repeated generic prose. Unknown colors are flagged for review, not claimed as palette facts.
- Integrated bulk upload, phone camera input, quick categories, batch edits, review existing items, save individually and optional AI suggestions. Existing IDs and photo paths survive edits.
- Experimental free local CLIP classification runs in a Web Worker, opt-in only. It downloads model files, suggests category/type, abstains on uncertain broad categories, and never auto-confirms labels. Does not infer color/fit or generate outfits. Transformers.js is pinned to 3.8.1. Device/network support and real-photo accuracy still require user testing.
- Cloud garment and inspiration analysis use the existing ThreadlineCloud session and deployed threadline-vision function. A configured key is explicitly not represented as verified balance. Each cloud image transfer is user-confirmed. No provider account/secret/billing changes were made.

## Validation
Run `node --test tests/*.test.cjs`. Tests exercise actual catalog variety, budget fallback, history, slot validation, invalid labels, unknown colors, actual main-app extension loading, direction rendering, existing-item review and signed-out AI errors.

## Remaining limits
The catalog is still 13 static reference products; live inventory/prices are not verified. Better discovery needs curated garment diversity, not simply more retailer names. Local CLIP is a category aid, not a fashion stylist or image generator. Cloud AI requires working API credits; full authenticated analysis and real-device local model inference have not been verified in automated tests.
