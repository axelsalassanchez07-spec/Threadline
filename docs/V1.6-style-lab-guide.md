# THREADLINE V1.6 — Three reusable testing labs

## What was built

One permanent test hub, with three sibling pages sharing a single local IndexedDB database:

- **Hub:** `/Threadline/lab/v16/`
- **Lab A — Wardrobe Scanner:** `/Threadline/lab/v16/wardrobe/`
- **Lab B — Inspiration Intelligence:** `/Threadline/lab/v16/inspiration/`
- **Lab C — Personal Stylist:** `/Threadline/lab/v16/stylist/`

These are **separate from production V1.5** and from the previous preview folders. No changes to root `index.html` or production Supabase data.

### Why there's no repeated Supabase setup

Every lab uses the same local IndexedDB database `threadline_v16_lab_records`, on the existing GitHub Pages origin. No OAuth redirect, SQL migration, Storage bucket, or Supabase test table is needed for these first-round UI and workflow tests.

The addresses above stay the same across iterations: change the static JS/CSS assets rather than creating a new Supabase callback or separate preview site each time.

**Limit:** This shared lab data is local to *one browser*. It doesn't automatically sync PC ↔ phone yet. Before cross-device/cloud acceptance tests, add a single stable staging environment or reuse an existing isolated staging table; never use the production `threadline_state` row for experiments.

### Current functionality (and what isn't ready yet)

**Lab A:** Select multiple clothing photographs (max 50 per batch); compress on device; propose tentative name/type from the filename and approximate color from image pixels; edit all fields; save one or all; avoid identical file imports via filename/size/date check; remove local test items. These are **heuristics**, *not* AI classification.

**Lab B:** Upload multiple inspiration photos; describe your interest; select styling characteristics; save and browse; display recurrent patterns from notes/tags and their frequency; send a saved reference to the Stylist. It does **not yet** visually analyze clothing, silhouettes, or fabrics in photos.

**Lab C:** Combine the local test wardrobe, stored inspiration cues and rated combinations. Generate Recreate, Reinterpret and Explore directions with Familiar/Balanced/Experimental controls; discourage recently repeated silhouettes and archived exact combinations; let user rate and review looks. Missing garment categories are filled with clearly labeled demo items rather than invented owned clothing. This is an experimental rule-based generator, not AI visualization or live retail inventory.

## Recommended UI test sequence

1. Open Lab A. Import 3–10 photos in one selection, confirm all previews load. Edit category, fit, color and tags. Save all. Refresh and verify local persistence. Re-select the same image and verify duplicate handling.
2. Open Lab B. Import at least 3 reference photos. For example, mark relaxed, wide-leg, and layered on several references. Save all. Confirm the frequency counts and saved images persist on refresh.
3. Click **Develop this look** on one saved inspiration. Lab C should open with that reference selected.
4. In Lab C, generate three directions. Confirm they differ in garments/proportions and show a clear demo label if the wardrobe is incomplete.
5. Switch Familiar, Balanced and Experimental. Confirm new recommendations display without losing the lab wardrobe.
6. Rate a look Love, Maybe, or Skip. Refresh. Confirm the rating remains in the archive and exact rated combinations aren't automatically returned.
7. Open your normal THREADLINE root website; confirm the existing account, wardrobe and photos are unchanged.

## When to enable actual visual AI

V1.6 needs **one shared vision-analysis endpoint**, not separate Supabase setup for every preview page. Build a Supabase Edge Function that accepts an authenticated image reference and task type (`garment` or `inspiration`), calls an appropriately configured vision model using a server-side API secret, and returns structured data with confidence/uncertainty markers.

The eventual browser client can reuse an existing signed-in session from the production THREADLINE origin (or one stable OAuth callback) and invoke the same endpoint from all three pages. Deploy this endpoint *once*, not per experiment. Image submission to a third-party vision service must be explicit and transparent. Require review before committing uncertain AI labels.

**Current status:** No paid image model or Edge Function has been configured, deployed or invoked. You can test all three local workflows without any AI key. Never put a secret API key in frontend JavaScript or GitHub.

## Stability and privacy

- Local test images are stored as compressed data URLs in IndexedDB.
- Browser storage may be removed if the user clears site data or works in a private browsing session.
- Test data is not synced to production or shared across devices.
- A filename cannot reliably identify a garment. Pixel-color estimates can reflect backgrounds and lighting.
- The Outfit Stylist uses small demonstration wardrobe fixtures to keep the UI testable with an empty closet. They are always labeled as demo pieces, not owned products.
- Test results should be reviewed before merging any V1.6 feature into the real application.
