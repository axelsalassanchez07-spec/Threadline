# THREADLINE V1.3 — Release and Migration Guide

**Status:** Cloud sync has been demonstrated by the project owner using a wardrobe item saved on PC and retrieved on phone through the /preview/ website. Production remains V1.2 until PR #1 is merged.

## What changes

- The root THREADLINE website keeps the same address and original visual design.
- Supabase GitHub sign-in and a cloud status bar appear below the navigation header.
- Wardrobe items, inspiration, saved looks, style preferences, ratings and shopping settings can be synced.
- Photos are uploaded to the PRIVATE `threadline-images` bucket. Data records reference private storage paths, not embedded image bytes.
- Browser-only use remains available without sign-in.

## Before merging PR #1

- Confirm the project database and user-scoped RLS rules from `supabase/setup.sql` are present.
- Confirm the `threadline-images` bucket is **private**, and user-scoped Storage RLS policies are active.
- Confirm GitHub OAuth sign-in works on the exact production URL `https://axelsalassanchez07-spec.github.io/Threadline/`.
- Confirm Supabase Authentication URL Configuration permits both the production address and the `/preview/` address.
- Export a JSON backup from the production V1.2 browser before switching.
- Optionally test one NEW item, a PNG/JPEG photo, save, refresh and signed-in sync from `/preview/`.
- Verify your current Supabase cloud wardrobe is still visible on the second device.
- Review the code changes, then merge the pull request to `main`.

## First production login — critical

The production V1.2 browser may have different data from the tested V1.3 preview. Production and preview intentionally use separate local browser stores.

1. Open `https://axelsalassanchez07-spec.github.io/Threadline/` after merge.
2. Sign in with the **same GitHub account** used on your successful preview test.
3. The app should report an existing cloud wardrobe.
4. Choose **Use saved cloud data**. This pulls the existing Supabase wardrobe into your production browser.
5. **Do not choose “Use this browser's data” unless you intentionally want to replace the Supabase snapshot.** The app warns before doing this.
6. Check wardrobe, inspiration, photos and saved looks, and test an additional small edit.
7. Repeat sign-in on your second device and verify the latest edit.

## Rollback

- The old production file is preserved in GitHub history; revert PR #1 to return the live root website to local-only V1.2 if necessary.
- Reverting does **not** delete cloud records from Supabase.
- Keep your local JSON backup until migration and photo tests are completed.

## Known limitations

- This is cloud backup/sync, not simultaneous collaborative realtime editing. Editing the same data on both devices at once can conflict; refresh the other device before making changes.
- Current cloud data are stored as one user-owned JSON row. This simplifies personal usage but is not a scalable multi-user shopping backend.
- Cloud images are accessed with temporary signed URLs and may need a page reload to refresh when expired.
- The first release does NOT add automatic Pinterest analysis, live retailer feeds, or paid product APIs.
- The publishable Supabase key is safe in browser code; **never commit database passwords, GitHub OAuth secrets, or service-role keys**.
