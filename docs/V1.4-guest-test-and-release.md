Status: **Awaiting guest-mode browser verification. Do not merge PR #2 yet.**

## Guest test (use a NEW private/incognito window)

Open:
https://axelsalassanchez07-spec.github.io/Threadline/v1-4-preview/

**Do not sign in during this test.** A private/incognito window avoids disturbing the authenticated session in the regular browser. Closing all private windows may delete that test data.

1. Open the V1.4 preview and confirm the top-right menu shows **Sign in** rather than an account name/email.
2. In **Outfit Studio**, generate a retail-product outfit. It should not request login.
3. Save an outfit, then refresh. Check that it stays saved during this private-browser session.
4. In **My wardrobe**, add an easily identifiable TEST clothing item. Check it remains after refreshing.
5. Open the account menu; verify it describes guest/local storage and offers a sign-in link.
6. Verify there is no cloud "Synced" claim for the guest data.
7. On a second device, the guest item should **not** appear automatically—guest storage is local only.

## Signed-in follow-up (normal browser)

- In the normal signed-in browser, verify the cloud wardrobe and existing photos still appear.
- Confirm linked GitHub and Google show as connected.
- The cloud sync controls must appear inside the account menu, not as a large full-page banner.
- Confirm the Google identity belongs to the original Supabase account; it must not create a second empty account.

## Sign-out privacy test (only after confirming cloud synced)

1. First export any important local backup. Confirm "Last successful sync" is recent.
2. Sign out from the account menu. The local copy of private cloud wardrobe data must disappear from this browser; the Supabase copy is **not** deleted.
3. While signed out, the app may be used locally as a guest.
4. Sign in again and choose **Use saved cloud data** to retrieve the same wardrobe. Never choose "Replace cloud with this device" on an empty/new browser unless you intentionally want to replace the existing cloud snapshot.

## Important known limitation

V1.4 does **not** automatically merge local guest items into an existing cloud wardrobe. When you sign into an account that already has cloud data, the app prompts you to choose a version. **Do not choose "Use this browser's data" on a guest test browser**, because that can overwrite the saved cloud snapshot. Export guest-only data first if you want to preserve it, and plan a deliberate merge feature later.

Email magic-link sending requires working Supabase email configuration and may be rate-limited. This is independent of Google/GitHub login; email remains a staged feature until verified.
