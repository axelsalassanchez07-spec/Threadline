# THREADLINE V1.5 — Cloud-test and production release guide

**Status:** All six guest-preview tests and the isolated two-way PC/phone archive synchronization test passed per the project owner. Production V1.4 remains live until this PR is merged.

## Why use a separate Supabase table?

Production lives in `public.threadline_state` and holds your real personal wardrobe and images. V1.5 cloud QA uses a different table, `public.threadline_v15_test_state`, with the same user-owned RLS rules. This prevents V1.5 test uploads from overwriting your real wardrobe data. Test photos use `<user-id>/v15-test/...` paths inside the existing private `threadline-images` bucket.

   `https://axelsalassanchez07-spec.github.io/Threadline/v1-5-sync-test/`
3. Keep the existing production URL and older redirect URLs; do not replace them.
4. Use your existing GitHub/Google account. Do not share any secret keys.

## Safe cross-device test

Open `https://axelsalassanchez07-spec.github.io/Threadline/v1-5-sync-test/` on your computer.

1. Confirm the page header says **V1.5 SYNC TEST**, not the production site.
2. Sign in with your existing Google or GitHub account.
3. If there is **no V1.5 test cloud backup**, select **Use this browser's data** to initialize the isolated test row. This does NOT replace `threadline_state`; it writes only to `threadline_v15_test_state`.
4. Add one identifiable test clothing item; generate an outfit; rate it Love or Maybe. Check that the exact combination appears under **Saved Outfits → Outfit archive**.
5. Open the account menu → Cloud storage → Sync now. Confirm a successful cloud sync status.
6. Open the **same test URL** on your phone, sign into the same account, and select **Use saved cloud data** if asked.
7. Confirm both the test wardrobe piece and the archived rating appear on your phone, and that the rated combination is not automatically suggested again.
8. Reverse the direction: rate a new look on your phone, sync, then on your computer choose **Restore cloud → this device**; confirm the new archive item appears.
9. Do not edit the two devices simultaneously; V1.5 cloud sync stores a single JSON snapshot and is not a realtime collaboration tool.
10. Open the **production V1.4** page and confirm the original wardrobe is unchanged.

**Note:** Supabase authentication sessions use the same browser origin for both the preview and production site. Signing out of the test preview may also sign you out of production in that browser; it does not delete cloud data.

## What V1.5 will change in production

- New discovery generator assembles combinations from the existing fixed catalog of 13 real products and your uploaded wardrobe; removes the fixed four-seed generator loop.
- Shopping budget constrains generation, where a combination exists; otherwise it reports the closest available cost honestly.
- Love / Maybe / Skip archives the exact look and automatically proposes a different combination.
- Rated exact combinations are excluded from automatic subsequent suggestions, but remain in the archive for deliberate reopening.
- Rated archive appears in both Saved Outfits and Shop Real Looks.
- Archive, recent looks, generated combination, and budget are all saved in the same Supabase cloud snapshot under `shoppingV11`. No change to the production database schema is required.

## Remaining limitations and next roadmap

1. **Expand catalog breadth:** With only 13 static products, the generator recombines known pieces; it does not discover new inventory. Genuine variety needs trusted retailer feeds or more user-curated products, along with stock and price checks.
2. **Clarify Studio vs Shop:** Outfit Studio should focus on styling decisions and wardrobe-first recommendations; Shop Real Looks should focus on purchasing missing pieces and affordable alternatives. Both can share a central generator.
3. **Richer feedback:** Ask what specifically worked (color, fit, silhouette, layering, occasion, garment) to improve recommendations without narrowing the user's style identity prematurely.
4. **Outfit visualization and inspiration:** Use actual inspiration photos (with appropriate image interpretation) rather than relying only on written tags.
5. **Realistic budgets:** Include a clear amount-to-buy, tax/shipping notice, and constraints. Mark catalog prices as references until live product APIs exist.
